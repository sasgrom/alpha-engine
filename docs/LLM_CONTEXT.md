## 5. Domain rules (normative)

- Form scope: 10-K, 10-Q, 8-K, /A amendments, DEF 14A.
- Canonical doc key: `CIK{padded10}/{accession-nodash}/{filename}` — identical layout in cloud storage and future local mirror.
- Series modes: `latest | first | as_of(T)`.
- Quarterly homogenization: flow concepts → 3M points; Q4 = FY(12M) − 9M YTD (`derivation=derived_q4`); stock concepts → instant at quarter ends.
- Concept aliasing — two layers (series.ts): (1) curated static map (ASC 606 renames); (2) per-company auto-alias for the `Current`/`Noncurrent` suffix rename family — canonical = the name with the latest periodEnd in THIS company's filings; merge only on hard evidence (all shared period values equal within 0.5%, or strict temporal succession + boundary medians within factor 2). Near-misses become `alias_candidate:<twin>:<reason>` continuity flags (value_mismatch / interleaved / boundary_jump) — review queue, never merged silently. Old names recorded in `aliased_from`.
- Restatement metrics per company: revision_rate, revision_magnitude, revision_lag_days, restatement_events (10-K/A count + 8-K Item 4.02).
- Continuity flags: gap, overlap, unit_change, sharp_revision (> threshold on expected quarterly grid from fiscalYearEnd), alias_candidate.

## 9. Known limitations (do not "fix" silently — discuss first)

- Full-text storage scope: test companies only (AAPL, MSFT); 10GB storage quota.
- Stream = scheduled cycles, not a daemon.
- Earnings call transcripts: external free source, experimental, `source=external`.
- Chunk inserts to hosted MySQL: ≤500 rows per INSERT (packet limits).
- XBRL concept names up to ~142 chars (column sized 200).
- iteration 3a: cloud gateway k3-agent = temperature=1 only (cloud scores are calibration, not bit-reproducible); drizzle-kit push broken (interactive TTY) → manual idempotent DDL via db/ddl/00N_*.sql + apply-ddl-00N.mts; vitest.config.ts needs `@db` alias for api tests; test/debug scripts must live in project root (node_modules resolution); sandbox may lose external network (ENETUNREACH) — fixtures pin Wikipedia shapes, live fetch must degrade to n/a; tsc incremental cache can mask errors — typecheck with `--incremental false` after any restore-like event; LLM/storage usage is billed to the site owner — surface token counts honestly (Lab page).
- iteration 3g: cloud runtime has NO outbound route to stooq.com/Yahoo (UND_ERR_CONNECT_TIMEOUT on every request — production `prices` job evidence) — price sync works only via the 3g bulk-import crutch or a future home worker; platform object storage hard-caps files at 100 MB (413 STORAGE_FILE_TOO_LARGE) and Hono bodies at 50 MB — hence 32 MB upload chunks.
- iteration 3i: the DEV sandbox and PRODUCTION share the same hosted MySQL — live QA scripts insert real job rows visible in the prod UI (clean them up); sweeps/cancels in QA affect prod rows too (this is how the two stuck prod jobs were cleared). In-process executors never survive a restart: orphaned running/queued rows are swept at boot (D25).

The LLM gateway may surface Chinese AiTransient strings ("无法连接网关…") — runner.humanizeError translates them before they reach jobs.message; legacy DB rows may still carry the raw text (displayed humanized only for new jobs).
